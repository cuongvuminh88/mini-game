05 · Kế hoạch test

Làm sao biết là xong.

Ca kiểm thử thủ công gắn với từng chức năng và quy tắc, cộng ma trận thiết bị. Game đạt khi mọi ca bắt buộc đều qua.

Cách test

  • Thủ công trên trình duyệt thật, mở trực tiếp index.html bằng file://.
  • Hỗ trợ test: cho phép ghi đè cấu hình qua tham số URL chỉ dùng khi test, ví dụ index.html?round=5000&up=3000 (lượt 5 giây, chuột hiện 3 giây) để kiểm tra nhanh. Khi không có tham số, dùng giá trị mặc định.
  • Đo thời gian: dùng đồng hồ bấm giờ điện thoại hoặc ghi màn hình, so với đồng hồ game.
  • Console: mở DevTools suốt quá trình test; bất kỳ lỗi đỏ nào đều tính là trượt ca TC-40.
  • Kết quả ghi vào cột “Kết quả” bằng: Đạt / Trượt / Chưa test, kèm trình duyệt và ngày.

Test tính năng đăng ký & quản trị Mới · 17/11/2026

  • Môi trường: chạy bằng docker compose up -d --build, mở http://localhost:3000 (không dùng file://, xem QT-90). File .env test có ADMIN_USER và ADMIN_PASSWORD ≥ 12 ký tự, không dùng mật khẩu thật.
  • Dữ liệu sạch: trước mỗi đợt test, docker compose down -v để xoá volume database, và xoá dữ liệu trang trên trình duyệt.
  • Kiểm tra database: docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"' rồi chạy câu SELECT, để đối chiếu với giao diện.
  • Gọi API trực tiếp bằng curl cho các ca máy chủ phải tự chặn (TC-56, TC-63, TC-91…). Chỉ dùng dữ liệu giả, ví dụ test01@example.com.
  • Ca TC-40 (không lỗi Console) áp dụng cho cả trang game và trang admin.
